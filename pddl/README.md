# PDDL Artifacts Directory

This directory contains PDDL (Planning Domain Definition Language) files used for AI planning.

**⚠️ Important**: These files are **NOT imported by Convex**. They are only used by external Python planning scripts.

## Directory Structure

```
pddl/
├── planning.ts              # PDDL configuration for LLM prompts
└── generated/               # Generated PDDL artifacts
    ├── domains/
    │   └── *.pddl          # PDDL domain definitions
    └── problems/
        └── */
            └── problem.pddl # PDDL problem definitions
```

## Workflow

1. **Generate PDDL** → `pnpm planning:refresh` reads from `convex/domainSpec/` + `pddl/planning.ts`, writes `.pddl` files here
2. **Run Planner** → Python script reads `.pddl` from here, writes `plan.json` to `convex/domainSpec/generated/problems/*/`
3. **Runtime Import** → Convex imports `plan.json` from `convex/domainSpec/generated/problems/*/`

## Files

### `planning.ts`

Optional configuration file that provides context for LLM-based PDDL generation. Describes:

- Planning domain verbs and predicates
- Available actions (ping, ssh, restart, etc.)
- Types and relationships

This file is read by `scripts/generate-pddl-llm.mjs` to provide context to the LLM.

### `generated/domains/*.pddl`

PDDL domain files that define:

- Types (room, item, enemy, server)
- Predicates (at-room, reachable, etc.)
- Actions (ping, move, take, use)

Generated by LLM from TypeScript schemas.

### `generated/problems/*/problem.pddl`

PDDL problem files that define:

- Initial state (player location, item positions, etc.)
- Goal state (what needs to be achieved)
- Objects (specific rooms, items, servers)

Generated by LLM from mission data.

## Why Separate from Convex?

The `.pddl` files are intermediate artifacts used only by the Python planner. Keeping them out of `convex/` prevents:

- Unnecessary bundling by Convex
- Confusion about what's imported at runtime
- Bloating the Convex deployment

Only `plan.json` (the planner output) needs to be in `convex/domainSpec/generated/` because it's imported by `data.ts`.

## Regenerating PDDL

To regenerate PDDL artifacts:

```bash
pnpm planning:refresh
```

This will:

1. Read from `convex/domainSpec/{schema,data}.ts` and `pddl/planning.ts`
2. Generate `.pddl` files in `pddl/generated/`
3. Run Fast Downward planner on `.pddl` files
4. Write `plan.json` to `convex/domainSpec/generated/problems/*/`
