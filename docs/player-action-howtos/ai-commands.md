# HOWTO: Add an AI-Driven Command

Use this pattern when a command should return realistic, context-aware output generated by a Convex agent (e.g., the existing `ping` implementation).

## When to Choose This Pattern

- You want dynamic, narrative-rich output tailored to the current game state.
- The command needs external reasoning or simulation beyond deterministic logic.
- Responses should be cached and reused when the same command-state combination repeats.

## Key Entry Points

- `convex/gameActions.ts` — `sendCommand` dispatches the command and caches hits before scheduling work.
- `convex/gameActions.ts` — `executeAsyncCommand` invokes the agent and handles mission feedback.
- `convex/agents/pingAgent.ts` — A full example of agent setup, tool wiring, caching, and error handling.
- `convex/utils/cacheUtils.ts` — `generateCacheKey`, `lookupCache`, `storeInCache`, and `incrementCacheHit` helpers.
- `docs/command-cache-implementation-plan.md` — Design principles for cache keys and lifecycle management.

## Implementation Steps

1. **Decide on the Command Verb**
   - Add it to `ASYNC_COMMANDS` so the request flows through the async pipeline.
   - Define any required arguments (target host, flags) and normalize them early in `sendCommand`.

2. **Create an Agent Module** (`convex/agents/<command>Agent.ts`)
   - Instantiate an `Agent` with a clear persona, instructions, and max steps.
   - Define any required tools via `createTool` to expose game context (network state, logs, inventory, etc.).
   - Export an `internalAction` (e.g., `execute<Command>NameCommand`) that:
     - Checks the cache using `generateCacheKey` and `lookupCache`.
     - Creates or continues a thread (`agent.createThread` / `agent.continueThread`).
     - Calls `thread.generateText` (or `run`) with prompts referencing the current room, threats, and other state.
     - Stores the result via `storeInCache` with `skillGained`, `success`, and `threadId` metadata.
     - Handles errors gracefully with informative fallback output.

       ```ts
       } catch (error) {
         console.error("Ping agent error:", error);
         return {
           output: [
             "ping: network error occurred",
             "Unable to reach target system",
             "Check network connectivity and try again",
           ],
           threadId,
           skillGained: 0,
           success: false,
         };
       }
       ```

### 2a. Type Safety Requirements

**CRITICAL**: All agent actions MUST use strict TypeScript types to avoid `any` anti-patterns (per CLAUDE.md guidelines).

**Required Imports**:

```typescript

import { type CommandResult, commandArgs, commandResult } from "../types";
```

**Action Signature**:

```typescript

  returns: commandResult,   // Validator from types.ts

    ctx,
    { target, gameState, threadId }
  ): Promise<CommandResult> => {  // Explicit return type
    // Implementation
  },
});
```

**Return Object Structure** (MUST include all fields):

```typescript
return {
  output: string[],      // Array of output lines for terminal display
  threadId?: string,     // Optional: agent thread ID for conversation continuity
  skillGained: number,   // Skill points earned (0 if cached/failed)
  success: boolean,      // Whether command succeeded
};
```

3. **Wire the Agent into `executeAsyncCommand`**
   - Add a `case` that calls `ctx.runAction(internal.agents.<command>Agent.execute...)`.
   - Merge agent output with mission validation feedback exactly like the `ping` branch.
   - Pass the `threadId` returned by the agent to `persistCommandGameState` so future invocations reuse context.

4. **Adjust Cache Strategy (If Needed)**
   - `generateCacheKey` normalizes the game state to four dimensions: current room, health category (`healthy`/`wounded`/`critical`), raw `threatLevel`, and the count of active (non-defeated) enemies in the room. These are hashed together with the command verb and target (see `convex/utils/cacheUtils.ts`).
   - If your command should react to additional context (inventory, mission progress, etc.), extend the normalization logic so the hash differentiates those cases. Keep the design notes in `docs/command-cache-implementation-plan.md` in sync.

5. **Update Tool Catalog (Optional)**

   If the command should be discoverable by players, update the appropriate documentation:

   **For `tools` listing** (displays when player types `tools`):
   - Add an entry to `toolCatalog` array in `convex/domainSpec/data.ts`
   - Include: `name`, `syntax`, `description`, `example`, `explanation`
   - This automatically updates the output of the `tools` command via `convex/gameData.ts`

   **For `help` command** (displays when player types `help`):
   - Update the hardcoded help text in `convex/gameActions.ts` (see `processSyncCommand`)
   - Only add commands here if they're general-purpose (like `look`, `missions`)
   - Most DevOps tools should only appear in the `tools` listing

6. **Testing and Observability**
   - Run the command twice in identical states to ensure cache hits increment instead of re-invoking the agent.
   - Validate mission feedback triggers when the command satisfies active objectives.
   - Monitor logs for tool usage events and agent errors.

## ⚠️ Cache Hit Side Effects Warning

**Principle**: Minimize side effects on cache hits. Every database operation costs **money** and **latency**.

### Current Cache Hit Path (see `sendCommand` in `gameActions.ts`)

On every cache hit, the system performs:

1. ✅ **Mission validation** - NECESSARY (updates progress, awards points)
2. ✅ **Terminal output insert** - NECESSARY (player sees output)
3. ✅ **Game state update** - NECESSARY (skill points, session state)
4. ⚠️ **Cache hit counter** - DEBATABLE (analytics only, not core functionality)

### Cost Analysis (Convex Pricing)

Convex charges **$2 per 1 million function calls**. Every query, mutation, and insert counts as a function call.

**Current cache hit cost**: 5+ function calls (more with multiple missions)

- `incrementCacheHit` mutation: 1 call
- `getActiveMissions` query: 1 call
- `validateAllMissionSteps` mutation: 1 + N calls (N = active missions)
- `terminalOutput` insert: 1 call
- `persistCommandGameState` mutation: 1 call

**Example**: 1M cache hits/month with 2 active missions = 7M function calls = **$14/month**

**Optimized** (remove counter, batch validation): 4M function calls = **$8/month** → **$6 saved (43% reduction)**

### Question Every Side Effect

Before adding operations to the cache hit path, ask:

- **Is this absolutely necessary for correctness?**
- **Can this be deferred or batched?**
- **Does this scale with player count or mission count?**
- **Is this analytics/metrics that could be async?**
- **What does this cost at scale?** (function calls × $2 per million)

**Example**: The cache hit counter (`incrementCacheHit`) costs $2 per million cache hits purely for analytics. Consider: Could this be batched? Async? Removed entirely?

**Rule of Thumb**: If removing it wouldn't break game functionality, it probably shouldn't be in the cache hit path.

## Verification Checklist

- [ ] Agent file resides in `convex/agents/` with exported `execute<Command>` action.
- [ ] **Type Safety**: Action uses `commandArgs` and `commandResult` validators from `types.ts`.
- [ ] **Type Safety**: Handler has explicit `Promise<CommandResult>` return type annotation.
- [ ] **Type Safety**: Return object includes all required fields: `output`, `threadId`, `skillGained`, `success`.
- [ ] **Error Handling**: `catch` block logs server-side error, returns friendly messaging, `success: false`, and `skillGained: 0`.
- [ ] Command is listed in `ASYNC_COMMANDS` and handled in `executeAsyncCommand`.
- [ ] Cache key generation, lookup, and storage follow the shared helpers.
- [ ] Mission validation feedback is appended to output lines when applicable.
- [ ] `persistCommandGameState` stores updated `skillPoints` and agent `threadId`.
- [ ] **Documentation**: If player-facing, command is added to `toolCatalog` in `convex/domainSpec/data.ts`.
- [ ] **Documentation**: If general-purpose, command is added to hardcoded help text in `processSyncCommand` function in `convex/gameActions.ts`.
